# test-mov

テストケースを **ego-browser** で実操作し、1 ケース 1 本の動画にする。動画には次が入る。

- 字幕（画面下の黒帯。「タイトル (ステップ i/n)」と、いま何を確かめているか）
- 字幕と同じ文の音声（VOICEVOX → macOS `say` → 音声なし、の順に使えるもの）
- 各ステップで見るべき要素の赤枠
- プレーヤーで切り替えられる字幕トラック（`mov_text`）

LLM が書くのは `scenario.json` だけ。録画・音声・組み立ては同梱の固定スクリプトがやる。

対象: `$ARGUMENTS`（空なら、直前の会話のテストケース一覧から推定し、どれを撮るかユーザーに確認する）

## 0. 依存を確かめる

```bash
bash "${CLAUDE_SKILL_DIR}/../../scripts/doctor.sh" mov
```

NG があれば、その直し方をユーザーに伝えて止まる。WARN（VOICEVOX が無いなど）は伝えて続けてよい。

## 1. 事前チェック（足りなければ質問する）

```bash
python3 -I "${CLAUDE_SKILL_DIR}/../../scripts/config.py" show
```

（`python3` が落ちるなら `/usr/bin/python3`）。テスト対象のプロジェクトのディレクトリで実行する。

次の 3 つを、**引数 → 設定 (`targets` / `preconditions`) → 会話** の順に探して埋める。

| 項目 | scenario.json のキー |
| --- | --- |
| 対象の URL かポート | `target` |
| 撮るテストケース（何を確かめ、何が出れば合格か） | `title`・`steps`・`expect` |
| 前提条件（ログイン状態・データ・フラグ） | `preconditions` |

- 1 つでも埋まらなければ、**`AskUserQuestion` でまとめて聞いてから進む**。推測で埋めない。`make.sh` も `target` と `preconditions` が無い scenario を拒否する。
- 設定の `notes` にプロジェクト固有の注意（DB の見方、URL の形、外部連携）があれば従う。

## 2. 準備

1. `Skill` ツールで `ego-browser` を起動し、その手順（`ego-browser skill`）に従う。
2. 対象 URL が応答するか確かめる。同じリポジトリの checkout / worktree が複数あるときは、ポートのプロセスが今の作業ツリーのものか確かめる（`lsof -a -p <PID> -d cwd`）。起動していなければ、起動してよいか聞いてから起動する。
3. 本物のアカウントでのログインは録画の前に済ませる（本物の認証情報を動画に映さない）。ログイン画面そのもののテストは、ダミー値で撮る。

## 3. 合格の条件を「実際の結果」で決める

- 期待値はコードを読んで決め、判定ロジックの場所を `file_path:line_number` で示す。
- 「ボタンが押せる」「画面が開ける」で合格にしない。**操作を完了した結果**（完了画面・反映された内容・エラー文言）を `expect` に入れる。
- 画面で止められるケースは、画面を迂回して（URL の直打ち、API への直接送信）サーバーでも止まるか確かめる。
- 保存・送信などデータを変えるステップ、決済・メール・外部サービスへの送信が起きるステップは、**実行前にユーザーに確認する**。
- 条件に合うデータが無いケースは撮らず、「データが無く未確認」と報告する。

## 4. scenario.json を書く

作業用ディレクトリ（スクラッチパッドがあればその下、例: `mov-<テスト名>-<日時>/`）に 1 ケース 1 ファイルで書く。

```json
{
  "title": "テスト #4 変更期限 ─ ケースA: 期限内",
  "target": "http://localhost:3051",
  "preconditions": ["予約 B123 が確定済み・期限内"],
  "steps": [
    { "say": "予約詳細を開き、変更期限の表示を確認します",
      "goto": "http://localhost:3051/reservations/B123",
      "mark": { "text": "変更期限", "up": 1 },
      "expect": "変更期限" },
    { "say": "変更ボタンを押すと、変更画面が開きます",
      "click": "予約を変更する",
      "mark": { "text": "変更内容の確認", "scope": "[role=\"dialog\"]" },
      "expect": ["変更内容の確認"] }
  ],
  "verdict": { "pass": "ケースAは合格です", "fail": "ケースAは不合格です。期待した表示が出ていません" }
}
```

| キー | 意味 |
| --- | --- |
| `target` / `preconditions` | 必須。手順 1 で埋めたもの（前提が無ければ `["なし"]`） |
| `say` | 字幕と音声になる文。「何を見ているか」と「期待どおりか」を短く（必須） |
| `goto` / `click` / `run` | 操作。`goto` は絶対 URL。`click` は表示文言が一致する要素（`{text, scope}` も可）。複雑な操作は `run` に JS 断片（`page` / `pause` / `task` / `checks` が使える） |
| `wait` | 操作後に画面が落ち着くまで待つ上限 ms（既定 4000） |
| `mark` | 赤枠の対象。`text`（一致する文言）、`up`（親へ上がる段数）、`scope`（ドロワー内は `[role="dialog"]`） |
| `expect` | 実画面の `innerText` に出ているべき文言（文字列か配列）。合否の根拠 |
| `verdict` | 結論のナレーション。全 `expect` の実結果で `pass` / `fail` が自動で選ばれる |
| `voice` / `video` / `screenshots` / `reading` | このケースだけ設定を上書きする（形は設定ファイルと同じ） |

- `say` に英語を書いてよい（読み上げ用にだけカタカナへ変換。字幕は元の表記）。辞書に無い語は警告が出るので、設定か scenario の `reading.words` に足す。
- `say` には漢数字で書く（`三日` を「みっか」と読ませるため）。字幕では `3日` になる。
- DB の新しいリビジョンなど画面に出ない結果は、`run` の中で `checks.xxx` に残すか、録画の前後に確かめて報告に書く。

## 5. 撮る

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/make.sh" <作業ディレクトリ> <出力名>.mp4 --data "${CLAUDE_PLUGIN_DATA}"
```

- テスト対象のプロジェクトのディレクトリで実行する（プロジェクト設定を読むため）。
- `--speed 2` で映像・音声・字幕を丸ごと倍速にする（既定は設定の `video.speed`）。
- 終了コード: `0` 全 `expect` 合格 / `1,2` 実行の失敗（メッセージを読む）/ `3` 赤枠の対象が見つからない（`result.json` の `found` を見て `mark` を直し撮り直す）/ `4` 動画はできたが `expect` が外れた（**不具合の疑いとして報告する**）。
- 音声はキャッシュされるので、撮り直しは速い。

## 6. 動画を確かめる

`<作業ディレクトリ>/sheet.png`（各ステップの最後の 1 枚を並べたもの）を `Read` で **1 回だけ**見る。

- 赤枠が正しい要素を囲んでいるか
- 字幕が赤枠や大事な情報を隠していないか
- 字幕の内容と画面が一致しているか

問題があれば `scenario.json` を直して手順 5 をやり直す（後から字幕や枠は足せない）。

## 7. 報告

- ケースごとに合格・不合格と、その根拠（実際に見えた文言・反映結果）を表で示す。
- 動画・作業用ディレクトリ・`shots/`（`screenshots` を有効にしたとき）は `file://` のクリック可能なリンクで示す。
- 撮れなかったケースと、テストとは別に気づいた点を分けて書く。
- 個人情報（氏名・電話番号・メールアドレス）が映っていれば、共有に注意するよう伝える。
- VOICEVOX で作った動画には、結論の字幕にクレジット（例: `VOICEVOX:春日部つむぎ`）が自動で入る。外に出すときは消さない。

## 守ること

- 操作はローカルの環境だけ。本番・ステージングは操作しない。
- コードは直さない。不具合を見つけたら報告で止める。
- 字幕には自分で書いた原稿だけを入れる（ページの内容を流し込まない）。
- 同梱スクリプトはケースごとに書き換えない。
- 並列で撮るときは、ケースごとに `video.taskSpace` と作業用ディレクトリを分け、同じデータを 2 つのエージェントで触らない。
- 生成物（フレーム・音声・mp4）はリポジトリにコミットしない。
